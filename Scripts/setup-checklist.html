Zeitkonto · setup runbook

Everything left that only you can do

The app is written, tested and green. What remains is the part a repository cannot reach: things that need an Apple account with your name on it, a bank account, and a card.

In order, because the order matters — two of these steps fail silently and confusingly if you do them in the wrong sequence. Tick as you go; the page remembers.

0 of 0 done

You need none of this to use the app yourself today

Clone the repository, open Hours.xcodeproj, press ⌘R. It runs in the simulator with no Apple account, no signing and no network. Everything below is about getting it off the simulator.

Phase 1 — free

Put it on your own iPhone

A free Apple ID is enough. You get the app on your phone; you do not get widgets, iCloud sync, or the ability to sell it.

  1. Free5 minutes

    developer.apple.com › Certificates, Identifiers & Profiles › Identifiers

    These are already set in the project, derived from the domain you own, so there is nothing to invent. What is left is telling Apple they exist: register the app identifier and the widget's, because an unregistered widget identifier is why a widget silently fails to install. The other two are test targets and never leave your machine.

    • App
    • Widget
    • Unit tests
    • UI tests

    If you change this, come back and change the three product identifiers in step 15 to match — they are prefixed with it.

  2. Free2 minutes

    Xcode › Hours target › Signing & Capabilities › Team

    The project deliberately ships with no DEVELOPMENT_TEAM set, so it does not carry someone else's account around. Choose your Apple ID from the dropdown and leave Automatically manage signing ticked. Do it for the HoursWidgetExtension target too.

  3. Free2 minutes

    iPhone › Settings › General › VPN & Device Management

    The first build onto a device installs but refuses to open, with an unhelpful message. Tap your developer certificate there and trust it. Once, per device.

    Free-account limit

    An app signed with a free Apple ID stops working after seven days and has to be rebuilt from Xcode. That is Apple's rule, not something in the code. It is the main reason to go to Phase 2 even if you never sell anything.

Phase 2 — the domain

Point zeitkonto.app at the site

Nothing here involves Apple and none of it costs anything beyond the domain you already own. Do it early anyway: DNS takes time to spread and the certificate takes longer, and the privacy policy URL has to resolve before a submission is accepted. The site itself is built and committed — this only connects the name to it.

  1. 5 minutesthen up to a day to spread

    Wherever you bought zeitkonto.app › DNS

    Four A records on the apex — the bare domain, often written @ — one for each of GitHub's Pages addresses:

    • A
    • A
    • A
    • A

    All four, not one: they are what makes it keep working when a server does not. Then, if you want www.zeitkonto.app to work as well, one CNAME record on www pointing at apectro.github.io — the repository owner, with no repository name after it.

  2. 2 minutesThen wait

    github.com/Apectro/Hours › Settings › Pages › Custom domain

    Enter zeitkonto.app and save. GitHub checks the DNS, then issues a certificate — that part can take anywhere from a few minutes to an hour. When Enforce HTTPS becomes tickable, tick it.

    docs/CNAME in the repository already says zeitkonto.app, so this should match what GitHub finds rather than fight it. That file is build output and is rewritten on every publish, which is deliberate: a hand-placed CNAME is the kind of thing a publish quietly clears.

  3. 1 minuteBlocks the listing

    Any browser

    • English
    • German
    • Policy

    .app is HTTPS-only, and this is where it bites. The whole .app top-level domain is on the browser preload list, so browsers refuse to speak plain HTTP to it — there is no insecure version to land on. Between the DNS resolving and the certificate being issued, the site is not slow or ugly, it is unreachable. That is normal, it is usually minutes, and the thing to do about it is wait rather than start changing settings.

    The old apectro.github.io/Hours/ address keeps working afterwards — Pages redirects it to the custom domain.

Phase 3 — $99 a year

Join the Developer Program

This is what unlocks the two features the code already contains but cannot switch on: the widgets and iCloud sync. Both are written, both are dormant, and both need a paid account for reasons that are Apple's, not the app's.

  1. $99 / yearBlocks 8–221–2 days to be approved

    developer.apple.com/programs

    Nothing below this line is possible without it. Approval usually takes a day or two and occasionally asks for identity documents, so start it before you need it rather than on the evening you want to ship.

  2. Needs step 710 minutesTurns on widgets

    Signing & Capabilities › + Capability › App Groups

    A widget runs in its own process and cannot open the app's database, so the app writes a small snapshot into a shared container and the widget reads that. The container is the App Group. Add the capability to the Hours target and to the HoursWidgetExtension target, ticking the same group on each:

    • Group

    That exact string is already in the code, at WidgetSnapshotStore.appGroupIdentifier. Use a different one if you prefer, and change it there to match. Until this is done the widgets say so on their face rather than showing a convincing screenful of zeroes.

  3. Needs step 710 minutesTurns on sync

    Signing & Capabilities › + Capability › iCloud

    Tick CloudKit and Key-value storage, then create the container. Days and holidays travel through CloudKit; your settings travel through key-value storage, because a second device computing expected hours from a different contracted week would produce wrong figures rather than merely different ones.

    • Container

    Already in the code at SyncPreference.containerIdentifier. If the switch is on but the entitlement is missing, the app quietly opens its local store and tells you — it never refuses to start. The switch itself takes effect at the next launch, because a store's iCloud setting is fixed at the moment it opens.

  4. Decision, not a task

    A day you delete is deleted on every device. The backup file in Settings › Backup and data is the only copy that survives losing the phone — plain readable JSON with every day, every holiday and all your settings. Write one somewhere before you trust the app with a year of hours.

Phase 4 — testing

Put it on a device with TestFlight

This is how you use the app on an iPad without a cable, and how anyone else tries it before it is on sale. Three separate Apple things are involved and confusing them is most of the difficulty: developer.apple.com is where identifiers and certificates live, App Store Connect is where the app record, the builds and TestFlight live, and Xcode is what makes a build and sends it. You never upload a file to a website by hand.

  1. 5 minutesBlocks everything below

    appstoreconnect.apple.com › Apps › +

    This is where the name is claimed. App Store names are unique across the whole store, so if Zeitkonto is taken you find out here, and it is worth doing before anything else is printed with it on. Pick the bundle identifier you registered in the previous phase from the list — if it is not there, it was never registered.

  2. 10 minutesNeeds a Mac

    Xcode › Product › Destination › Any iOS Device, then Product › Archive

    Archiving builds a signed, installable version — which is why it cannot be done on a simulator, and why the destination has to be a device. When it finishes, the Organizer window opens: Distribute App › TestFlight & App Store. That sends it straight to App Store Connect. There is no file to save and no page to drag it onto.

    Expect a few minutes of processing after the upload, and an email if it is rejected for something mechanical — a missing icon size, a privacy string.

  3. 2 minutesThen it is on the iPad

    App Store Connect › your app › TestFlight › Internal Testing

    Internal testers are people on your own team, up to 100, and their builds need no review — the build is available within minutes. External testers, up to 10,000 by email or public link, need a short beta review for the first build of each version, usually a day.

    Then on the iPad: install TestFlight from the App Store, sign in with the same Apple Account, accept the invitation, and the app is there. Every later build you upload appears in the same place, so this is the last time you touch a cable.

    A TestFlight build stops working 90 days after upload. That is an expiry on the build, not on anything you have done wrong.

Phase 5 — only if you sell it

Switch on Zeitkonto Pro

Skip this entirely if the app is just for you — everything works unpaid in a build you sign yourself. The order in this phase is not a suggestion: step 14 done before step 15 wastes an afternoon.

  1. Do this firstDays, if the bank details bounce

    App Store Connect › Business › Agreements, Tax, and Banking

    The expensive mistake

    Until this agreement is signed and your bank and tax details are accepted, StoreKit returns zero products and no error. The paywall renders empty, the app looks broken, and nothing anywhere tells you why. People lose a day to this.

    Sign it before you create the products, not after.

  2. 20 minutesIdentifiers must match exactly

    App Store Connect › your app › Monetization

    The identifiers must match SubscriptionStore.ProductID character for character. A typo here is another silent empty paywall.

    • Monthly
    • Yearly
    • Lifetime

    Monthly and yearly are auto-renewable subscriptions in one shared group — call it hours.pro — so someone can move between them. Lifetime is a non-consumable. Each needs a display name, a description and a price before it will even appear.

    If you ever change the bundle identifier, change these three constants in Hours/Data/Store/SubscriptionStore.swift to match your new prefix.

  3. Decision

    The numbers in HoursTests/Hours.storekit — £1.99 monthly, £12.99 yearly, £24.99 outright — were chosen to make the paywall render in the simulator. They are placeholders, not a recommendation. The real prices live only in App Store Connect.

    Worth remembering what is and is not behind the payment: recording hours is free forever, and nothing already recorded is ever withheld — if a subscription lapses every figure is still there and the backup still writes. What is paid for is producing and creating: the exports, the widgets, a second job, editing a range in one pass, and iCloud sync.

  4. Easy to miss1 minute

    Product › Scheme › Edit Scheme › Run › Options › StoreKit Configuration → None

    The Hours scheme currently points Run and Test at HoursTests/Hours.storekit, which is what lets you exercise buying, cancelling, expiring and refunding in the simulator with no account and no network. It is genuinely useful — right up to the moment you want to test a real sandbox purchase.

    While that file is selected, Xcode serves it instead of talking to App Store Connect. A product you have configured perfectly will still look missing. Set it to None when you want the real thing, and put it back afterwards.

Phase 6 — submission

The listing itself

The part that is writing rather than configuration. Two of these will get the build rejected if they are missing.

  1. Rejected without itPlaceholder is in place

    Hours/Resources/Assets.xcassets/AppIcon.appiconset/

    There was no icon at all — the asset catalogue declared a 1024×1024 slot and held no image, which App Store Connect refuses at upload. There is now a real one: four rules of a timesheet, one of them run long and picked out in amber.

    It is drawn by Scripts/make-app-icon.py rather than committed as an opaque binary, so the geometry and the colours are a dozen editable numbers at the top of the file. Run it again after changing them. Treat it as a working placeholder — it clears the blocker and it is not embarrassing, but it is not a designed identity either.

    If you replace it by hand: 1024×1024, no alpha channel (iOS rejects transparency in an icon), square — the system applies its own rounded mask.

  2. Mostly done for you30 minutes

    github.com/Apectro/Hours › branch screenshots

    They already exist. A test drives the app in a simulator with a month of sample data and captures the calendar, a day, the insights, settings, the privacy screen and the export sheet — plus the actual exported PDF pages, CSV and XLSX. Ten files, on the screenshots branch, kept current.

    Two sizes are now captured for you: the suite runs on the largest iPhone the runner has, then takes the screenshots again on a smaller one. They arrive in a folder each, named after the simulator, so they can be uploaded separately without sorting them out first. The last run gave iPhone-17-Pro-Max and iPhone-17-Pro.

    The 6.9-inch set is the one App Store Connect requires, and that is the Pro Max folder. The second size is there to choose from, not because Apple demands it — and note that a genuine 6.5-inch device (an iPhone 11 Pro Max) is not installed on the runner, so if your listing specifically needs that size you will have to take it by hand.

    That job runs on pull requests and on demand, not on every push — Actions › Build and test › Run workflow.

  3. Rejected without itWritten for you10 minutes

    docs/privacy/index.html

    Every App Store listing needs a privacy policy URL that resolves, even one for an app that collects nothing. The policy is written — from the code rather than from a template, with a table in docs/README.md showing where each claim comes from, so it can be checked rather than trusted.

    Pages already serves it from main:/docs; once the domain is attached in phase 2 it is live at: It appears at:

    • URL

    Two edits before you do: the contact address says REPLACE-WITH-YOUR-CONTACT-EMAIL, and the date at the top should be the day you publish.

    Interacts with step 26

    Making the repository private stops Pages serving on a free plan, and the URL dies — which fails review at your next submission. Host the page elsewhere first, or keep the repository public.

  4. Ten minutes of ticking "No"

    App Store Connect › App Privacy

    Data Not Collected, in every category. This is the easiest form you will ever fill in, and it is worth being able to answer it honestly — most apps cannot.

  5. Drafted for you30 minutes to edit

    docs/app-store-listing.md

    Every field App Store Connect asks for is drafted, with the character limit it enforces marked against each: name, subtitle, promotional text, the full description, keywords, URLs, age rating and the review notes. The category is already set in the project to Productivity.

    The review notes are the ones worth reading before you send. They say plainly that the app is fully functional unpaid and how to reach the paywall — reviewers reject paywalls they cannot get behind, and this one gates producing timesheets rather than recording hours, which is not obvious from outside.

    Three things in it still need you: confirming Zeitkonto is free to claim, the prices, and the contact email.

Phase 8 — only if you want it

Genuinely optional

Nothing here blocks anything. Listed so you know it exists rather than discovering it later.

  1. Half a day per language

    The app is English only. The string catalogues are wired up and working — nineteen keys across the app and the widget — so adding a language is mostly translation rather than plumbing.

    Two strings would need moving into a catalogue first: the reminder notification's fallback body in ReminderScheduler, and the gap message built in GapFinder.message. Both are literal English inside the engine, which imports nothing but Foundation on purpose.

  2. A few minutes

    Nothing in it is secret — there are no keys, no tokens and no personal data anywhere in the tree, and the CI runs without any secret at all. But the App Store listing does not link to it, and a private repository is one fewer thing to think about.

If you only do one phase, do the first. Three steps, no money, and the app is on your phone this afternoon. Everything after that is about other people being able to use it.

The two steps worth reading twice before you start are 8 and 11 — both fail by showing you an empty paywall with no error, and both are ten seconds to fix once you know.
